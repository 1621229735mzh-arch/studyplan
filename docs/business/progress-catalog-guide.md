# 课程与资料目录导入说明（版本 1）

目录用于“学了什么、完成多少”，不包含日期安排，不修改今日或计划。导入前从进度页下载当前科目、单位和任务目录，把它与本文一起提供给外部 AI。网站内没有模型调用。

## 流程

上传 JSON 或手动整理课程 → Java 校验 → 可读预览（完整总量变化、全部提交条目、任务归属）→ 核对确认 → 事务保存。预览有效期 15 分钟；目录、相关任务或科目单位变化后需重新预览。失败保留输入。

## 文件格式

参见 `progress-catalog.schema.json` 与 `progress-catalog-example.json`。根对象只有 `schemaVersion: 1` 与 `courses`。

每门课程：

- `key`：稳定的英文标识，1—64 位字母、数字、下划线或短横线。追加同一课程时沿用它，换 key 会创建另一门课程。
- `direction`：MATH（数学）、ENGLISH（英语）、POLITICS（政治）、CS408（408）。
- `branch`：分科名称，例如高等数学、线性代数、概率论、阅读、数据结构。
- `title`：课程或资料名称，最多 200 字；branch 最多 100 字。
- `subjectId` / `unitId`：当前目录中真实的整数 ID。已有课程不能改变科目或单位；一门课程只能用一种单位。
- `nodes`：完整目录，可含章节与末级条目。

每个目录项：

- `key`：课程内稳定且唯一的标识，规则与课程 key 相同。
- `parentKey`：同课程的父目录 key；顶层用 null。
- `title`：内容名称，最多 200 字。
- `totalAmount`：末级条目的完整总量，须为正数，最多 6 位小数、12 位整数；章节容器用 null。
- `sortOrder`：0—100000，决定同级顺序。
- `taskIds`：已有任务 ID 列表；无关联填 []。仅末级条目能关联任务。科目、单位须与课程一致，一个任务只能属于一个目录项。

目录最多 8 层。单次文件最大 2 MB、100 门课程、2000 项目录。拒绝重复字段、未知字段、字符串数量、循环或不存在的父目录。

## 总量与追加

课程总量是末级条目的数量之和。例如有 80 讲，即使计划只安排前 20 讲，目录仍应包含全部 80 讲。未知的目录不要编造，可以先手动核对资料目录。

同 key 的目录项被更新，新 key 的条目被追加；文件中没写的已有条目保留。因此多次导入同一文件不会增加重复总量。没有删除历史目录的隐式操作。已有任务或学习记录归属的末级条目不能直接改成章节容器。

预览展示原总量与新总量，必须核对后确认。单次确认失败整笔回滚；同一预览令牌重试不会重复应用。

## 完成量与归属

完成量来自已有学习记录，不在目录文件中导入“已完成”数字。目录不创建任务、不改变安排、不生成学习记录。

任务明确关联到目录后，其历史和后续学习记录自动累计。没有明确关联的记录先计入学科累计，再由本人归类到同科目、同单位的末级条目。不会通过标题猜测归属。

目录项累计量可超过自身总量，但课程环形图对各末级项分别封顶，避免重复学习一讲抵掉未学的一讲。学科累计与课程的“实际累计”仍保留真实学习数量。修改或删除记录后实时重算，复习不重复计入首次学习量。

归类检查原记录版本与目录版本；目录变更检查预览上下文。学习记录改变任务、科目或单位后，不匹配的归属不再计入课程，返回待归类。
