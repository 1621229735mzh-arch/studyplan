# 外部规划上下文导出 v1

入口：学习计划页的“导出规划上下文”。联网读取完成后，选择下载Markdown或JSON；两种格式共享本次读取的事实、数据版本及导出时刻。需要最新数据时点击“重新读取”，关闭再打开也会重新读取。手机入口换行，继续使用原Blob下载能力；安卓WebView保存沿用现有客户端的导出适配，本轮未实机验收。

## 文件内容

- 全部科目与单位（包含停用项）、阶段目标、所有现存任务及版本，不受当前页面科目或日期筛选影响。
- 完整课程／资料目录、课程与节点稳定ID、任务关联、原服务计算的完成量或内容百分比；不混加不同单位、不把内容百分比换算为讲数／题数。
- 原方案标识、起止日期、月周纲要、参考日安排及同日有效首次学习量；按书接续教材ID、内容顺序、参考日期和题目模式／清单单列。参考日期不等于实际学习日期。
- 全部有效学习记录、完整复习反馈历史、复习项和来源ID、原待执行／到期日期、教材自动复习开关与暂停／来源有效状态。已软删除的学习记录不导出；无记录的任务保留。
- 最近30个学习日（含首尾）的学习次数、学习天数、按科目／单位分列的首次量和复习量、复习次数及证据记录ID；学习内容与复盘原文保留在完整记录中。未来日期和更早记录保留于历史，不混入近期摘要。
- 薄弱项仅取每个未归档复习项截至当前学习日的最新非空真实反馈，列出不会／模糊、反馈日期及证据ID；更新为掌握后不再列为当前薄弱项。没有反馈不推断掌握或遗忘率。
- 未处理问题以OPEN备忘录原文为准，保留备忘录ID、科目、到期日、版本及已转换任务ID；DONE备忘录不列入。当前没有结构化错题清单，不能声称已覆盖所有学习问题。

已记录数量与未知数量分开表达：COUNT_STUDY／COUNT_REVIEW任务的历史数量全部未知时，对应任务实际量未知（服务端值为null，JSON沿用全站非空字段策略省略该字段，Markdown显示“未记录”），`unknownQuantityRecords`保留未知次数；近期按单位合计是“已记录量”，另外给出`unknownFirstStudyRecords`／`unknownReviewRecords`。不推算历史单词数。部分复习只保留进度，不当作已完成复习；复习不增加首次学习量。用时无需录入，历史值只作原始事实保留。

## API 与可移植格式

`GET /api/plan/context-export`仅允许现有认证会话，返回`Cache-Control: no-store`：

```text
{
  snapshot: {
    schemaVersion: 1,
    documentType: "408doing.planning-context",
    exportedAt, dataVersion, studyDate, recentFrom, recentTo,
    rules, facts, feedback
  },
  markdown: "同一快照生成的Markdown文本"
}
```

JSON下载内容为`snapshot`本身，包含明确字段的DTO，不含响应包装或第二份Markdown。Markdown按科目目录、任务、参考安排、完整记录、反馈、问题等分节展示，转义用户文本中的表格符号、换行及HTML，不执行其中的文本或指令。

`exportedAt`为带`+08:00`偏移的真实时刻；`studyDate`遵循北京时间09:00切换。`dataVersion`是对学习日、摘要范围、规则、事实及摘要的SHA-256指纹，排除真实导出时刻。相同学习日内事实不变时指纹不变，修改／删除记录或修改导出范围内内容会改变指纹；学习日变化也会改变指纹。任务、目标、复习项、备忘录等同时保留各自版本，课程和计划保留原工作区版本。指纹仅表示这份上下文，不是数据库全局版本，也不是未来更新接口的授权或并发凭证。

导出在单个MySQL REPEATABLE_READ只读事务中执行，调用现有业务读服务，不运行自动复习对账、不改期、不生成记录、不写第二份完成事实。账号、会话、提交令牌、密码与环境配置不在导出DTO中。服务端不保存文件；浏览器不缓存这份完整上下文，弹窗关闭／断网时清除内存快照，读取失败可重试。

## 交接与后续边界

可向外部规划工具说明：“依据真实学习记录和反馈讨论下一阶段调整，引用已有课程、任务ID；参考安排与真实执行分开看，先给出建议与理由。”

这是只读上下文合同，不能提交到现有计划导入API，不是数据库备份。当前不实现调整前后差异预览、更新既有安排或模型调用；后续调整流程需重新读取、核对稳定ID与数据版本，并由本人确认后通过正常业务服务应用。不能通过改planId再追加同名计划替代更新。
