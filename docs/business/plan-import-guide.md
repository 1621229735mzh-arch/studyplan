# 外部 AI 学习规划书与 JSON 导入规范（v1—v5）

把本文件、同目录 `plan-import.schema.json` 和从网站下载的“我的规划目录.json”交给外部 AI。先在外部讨论确定学习材料、目标、起止日期和每日安排，再让 AI 输出可导入的 JSON。网站没有内置 AI 生成入口，也不会向模型发送学习数据。

## 使用流程

1. 在计划页点击“导入外部方案”，下载规划书、格式规范和当前科目/单位目录。
2. 把材料和实际需求给外部 AI，要求按本规范生成完整方案。示例文件中的科目、单位必须替换成你的目录中的准确名称。
3. 保存为 UTF-8 `.json` 文件，上传或粘贴到网站。文件最多 2,000,000 字节；不包含 Markdown 代码围栏、解释文字或注释。
4. 点击“校验并预览”，逐页查看日期、内容、数量、预计用时及疑似重复提示。
5. 勾选核对确认，点击“确认追加”。已有安排和学习记录保留；全部成功才会保存，失败不留下半份方案。

## 数据层级

整体标题 → 阶段目标（可选）→ 月/周目标说明 → 每日任务安排。

日安排是排期数量的唯一来源，月、周不另填数量。手动日安排和外部方案进入同一套视图。完成量来自学习记录，导入计划不会产生完成量。不同科目或单位分别展示，不生成混合百分比。具体复习项仍由复习模块管理；v3 可安排回顾、复盘与订正时段，只计用时，不预建具体复习项。

## 顶层字段

| 字段 | 含义 |
| --- | --- |
| schemaVersion | 普通任务用 `1`；含有序接续任务用 `2`，规则见下文 |
| planId | 方案唯一标识，1—64 位英文字母、数字、下划线或连字符；同一方案重试保持不变 |
| title | 整体计划标题，最多 200 字符 |
| startDate / endDate | 真实日期 `YYYY-MM-DD`，包含首尾两天 |
| goals | 阶段目标数组；没有阶段目标可填空数组 |
| months | 每个月一条月目标说明，覆盖整个起止区间 |
| weeks | 每周一条周目标说明，覆盖整个起止区间；周一作为 startDate |
| tasks | 任务定义；同一任务跨多天使用相同 key |
| days | 整个起止区间的逐日安排；每个日期恰好一次，休息日为 `items: []` |

所有顶层字段必填。不能添加未定义字段；JSON 对象中不能有重复字段。数组顺序不影响日期归属。周一可能早于整个计划的开始日期，但所在周必须与计划区间相交。

## 子项字段

- goals：`key`（最多 64）、`subject`（准确科目名）、`title`、`description`（可省略或 null，最多 1000）、`startDate`、`endDate`。日期在整体区间内。
- months：`month`（YYYY-MM）、`title`、`description`（可省略或 null）。每个月唯一。
- weeks：`startDate`（周一日期）、`title`、`description`（可省略或 null）。每周唯一。
- tasks：`key`（最多 64）、`subject`、`unit`（准确单位名）、`title`、`goalKey`（可省略或 null）、`plannedAmount`。引用目标时必须同科目，相关日安排必须在目标日期范围内。
- days：`date`、`items`。每条 item 包含 `taskKey`、`amount`、`estimatedMinutes`（可省略或 null，表示未估算）。同一任务同一天只出现一次。

任务 key、目标 key 各自在文件内唯一。数量必须是 JSON 数字，范围 0.01—99999999.99，最多两位小数；每个任务的 plannedAmount 必须严格等于该任务所有日安排 amount 之和。所有任务都必须有日安排。不支持使用字符串 `"10"` 代替数字 `10`。

预计用时为非负整数分钟，缺失不是零。网站不因导入成功而宣称符合时间预算。科目/单位必须已经配置且启用，不自动创建；先在设置中配置，再重新下载目录。

## 校验、追加与调整

- 文件格式、真实日期、引用、目录、数量合计任一校验失败，整份不导入；按错误字段修改，再重新预览。
- 同一 planId 或内容指纹已导入时拒绝再次追加。修改 planId 或重新排列数组不能重导相同内容。它不是“更新已有计划”的接口。
- 预览提示相同日期、相同科目、同名任务，最多展示 100 条提示。系统无法判断不同名称是否语义重复，需要本人核对；确认后仍追加新任务。
- 预览后文件或相关数据变化时，确认会拒绝并要求重新预览。确认请求必须携带服务器返回的 previewToken。
- 导入后的局部调整在对应日期中完成。更改或删除安排不会删除已有学习记录；未完成任务不自动顺延。
- 输入保护：最长 5000 天、20000 个任务、总共 20000 条日安排，每日最多 2000 条。不是备考预算规则。

## 给外部 AI 的提示词

> 根据我确认的学习目标、材料、起止日期与可用时间制定完整学习计划。先与我讨论内容，再按随附的 plan-import.schema.json 输出单个 JSON 对象，不要添加注释、代码围栏或解释。
>
> 严格使用“我的规划目录.json”中的科目和单位名称。输出整体标题、月目标、周目标与全部日期的日任务；休息日也列出日期并填空 items。复用 tasks 中的任务 key，正确累计各任务 plannedAmount。未知预计用时填 null，不编造满足预算的结论。日期用真实 YYYY-MM-DD，周从周一开始。输出前检查重复日期、缺失日期、任务引用和数量之和。
>
> 我确认的实际需求如下：（填写材料、目标、开始/结束日期、休息安排及其他限制。）

## 开发接口

- `POST /api/plan/imports/preview`：`{"document":"原始 JSON 文件全文"}`。
- `POST /api/plan/imports/confirm`：同上，另带 `previewToken`。
- document 使用原始字符串，不先解析再序列化，以便服务端检查重复键。
- 需登录和 CSRF。校验失败通常返回 400；重复导入/过期预览返回 409。
- JSON Schema 负责形状；日期区间、目录存在性、合计、防重等跨字段规则由 Java 负责。

## 有序接续任务（版本 2）

需要“每天一个名额，完成当前题后才推进”时，使用版本 2 并声明 `tasks[].sequence`，不要仅在描述里写规则。
`mode` 固定为 `COMPLETE_THEN_ADVANCE`；`items` 按顺序列出每题的 `key`、`title`、HTTPS `url`。
题目数等于任务 `plannedAmount`，每日该任务 `amount` 固定为 1；同一任务每天最多出现一次。
预览会显示完整清单和规则。完成整题才记 1，尝试只记用时，漏做名额不累计，结束日期不延长。
见 [完整接续规则与字段示例](sequential-practice.md)。旧 v1 导入不受影响。

## 时间型安排（版本 3）

适用于按时间学习、题量尚未核实的计划。任务的 `plannedAmount` 和每日 `amount` 明确填 null，`estimatedMinutes` 为 1—1440 的基本分钟数，不使用零或虚构题量。任务新增 `activity`：

- `mode`：`TIMED_STUDY`（实际首次完成量可选填）或 `RECAP`（复盘／回顾／订正只计用时）。
- `description`：材料、操作步骤和进度位置说明，最多 1000 字。
- `flexibleMinutes`：0—1440 分钟的可追加上限；不自动计入基本预计用时。

时间型任务不能同时声明 `sequence`。v3 中普通数量任务仍必须填写正数及对应数量之和。一天可分别安排理解、首次练习、回顾和订正，使首次完成量与复做分开。

今日提供“记一笔”和“结束本次”，记录本次用时、可选实际首次完成量及教材页码／最后题号／卡点。“结束本次”只表示当天安排收工，不表示整讲完成；不会把预算转换成题数。复盘任务在后端禁止通过新建或修改记录增加完成量。修改、删除记录后同步重算，未完成内容不自动顺延。

## 完成确认型安排（版本 4）

v4 兼容原数量、接续与时间型安排，新增 CHECK_ONLY。任务仍需真实科目及单位作为归属元数据，但不产生该单位的完成量，不使用虚构的“1词／1次”或0分钟模拟完成。

任务字段示例：
```json
{"key":"daily-review","subject":"英语一","unit":"词","title":"每日单词复习","plannedAmount":null,"activity":{"mode":"CHECK_ONLY","description":"复习已学单词；不增加新词量","flexibleMinutes":0}}
```
日安排示例：`{"taskKey":"daily-review","amount":null,"estimatedMinutes":null}`。版本4或5，数量和预计用时均为空，弹性为0，不可同时声明题目序列。Java额外核验关联的日安排规则。

同一任务可跨天使用，每天独立确认或取消；一天只保留一份有效确认。无需数量、用时或掌握评分，不列为缺失用时，不参与学习量合计。未完成不挪到次日，不生成欠账。具体复习内容来自已学内容和本人／外部软件，不预建复习模块的具体复习项。

## 按书学习接续（版本 5）

用于本次确认的张宇高数学习方式，也可以显式用于其他书籍。普通任务、每日一题、时间型和完成确认型的原规则继续兼容。

任务使用 `activity.mode: "CONTINUED_STUDY"`，`plannedAmount` 和日安排 `amount` 均为 null，`flexibleMinutes` 为 0。`activity.description` 写具体知识点或练习范围；省去操作说明。`unit` 仅作为原有目录归属，百分比不转换成题数、讲数或课程完成量。

新增任务字段：

```json
"continuation": {"streamKey":"textbook","title":"《基础30讲》高数主教材","position":1}
```

- 同一本书使用同一 `streamKey` 和名称，科目一致；不同导入批次的同名 key 独立。
- `position` 从 1 连续递增且不重复。每份内容有独立 task key，只有一个日安排；同一本书的参考日期按顺序逐日连续。
- 日安排预计用时为 1—1440 分钟。张宇方案每日两本书新增内容合计 120 分钟，比例可随内容调整；这是本方案安排方式，不是所有用户的固定预算规则。
- `endDate` 覆盖参考日期。实际学习可以延后到参考结束日期之外，不需要预建数百份重复日安排。
- 完成确认型任务在 v5 中仍可使用，遵守原有无数量、无预计用时的规则。

今日按书收纳内容，旧内容与新内容各自保留累计百分比：

| 当天事实 | 下一日期的执行内容 |
| --- | --- |
| A 完全未推进 | 仍是 A，漏做日期不积累新内容 |
| A 完成 40% | A 剩余 60% ＋ B |
| 只收尾 A，B 未推进 | 仍是 B，不加入 C |
| A 收尾，B 推进到 30% | B 剩余 70% ＋ C |
| A 完成 100% | B |

新内容进入安排后，必须有该内容的正百分比增量记录，才在下一日期带入后一份；只增加用时不算推进。每次最多解锁下一份，同一天完成后也不会连续带入数份。已有剩余内容允许使当天预计用时超过 120 分钟。两本书独立，不设置教材与题册的先后限制。

`POST /api/learning/records/day-progress` 沿用任务、日期、累计 `completionPercent`（0—100 整数）、本次用时、revision 和 clientToken。相同百分比只计用时；例如从 40 到 70 只保存 30 个百分点。进度增量保存在原学习记录的 `continuationDelta` 中，`amount` 始终为空，学习量统计不会混入百分比。

删除记录后重算累计进度和接续位置；保留后续记录真实内容身份。记录页可以修改本次用时和文字，百分比更正使用删除后重新填写，日期和任务身份不直接改挂。历史补记不能使包括后续日期在内的累计进度超过 100%。各书共享行锁防止不同内容的并发操作绕过检查，revision 包含全书计划版本和包括删除历史在内的记录版本。

计划日历保留原始参考安排，今日页根据实际记录派生执行内容；日历中的参考结束日期不表示已经完成或必须停止。普通任务不自动顺延的规则不变。离线只展示已同步的今日快照，不在本地推进或提交。

[首周可导入样例](plan-import-continuation-example.json)示范两本书分组、内容描述和每日 120 分钟的可变比例；它不是完整一轮计划，也不替换已经导入的旧方案。样例的知识主题是规划拆分，非实书小节编号；题号参考[2027 公开讲题索引](https://www.bilibili.com/list/ml2581072681?bvid=BV1HfBSB6ECN&oid=115779332800830)，未据此断言全章总题数。预计用时是初始估算。
