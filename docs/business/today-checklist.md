# 今日清单（2026-10-01 用户确认）

本次需求细化 `PLAN.md` 的今日安排：页面默认按数学一、英语一、政治、408 展示。用户当前要求优先于总纲中“其他科目可配置”的通用展示方式；设置仍保留现有科目，数据结构、组成原理、操作系统、计算机网络合并展示到 408。旧数据中其他科目和未分类记录保留额外分区，防止隐藏用时。

## 时间与清单

- 顶端仅显示已学习、预计剩余。已学习包括当日学习记录和复习记录的实际用时，完成任务的用时继续计入。
- 学科分区分别显示这两个时间，顶端严格合计各分区。时间估算显示到 0.1 分钟：先按任务四舍五入，再合计分区与顶端，避免不同层次显示出不一致的合计。
- 未完成学习和复习同在清单；已完成放入可折叠列表。完成仅指当日安排，不改变跨日期任务的总状态。
- 同任务在同日多个学习安排来源合并成一行：计划量、预计用时分别相加，实际完成量与用时只计算一次。复习不合并进首次学习量。
- 计划外记录继续计入实际时长，补记入口默认折叠。取消安排后的复习部分记录保留实际用时，不继续列入待完成任务。
- 预计用时来自用户录入的外部 AI 计划。每日安排增加预计分钟输入，缺失显示待补充；顶端/分区显示已知时间下界“至少”，不把未知估算当成已知的 0。
- 原学习预算、复习额度及预算校验仍用于设置与安排，今日页不再展示这些预算卡片。当前不接入站内 AI。

## 两个操作

**完成**：填写本次用时，保存累计完成 100%。复习完成时还需选择不会、模糊或掌握，才推导下次日期。

**剩余**：填写累计已完成百分比和本次用时。30 表示完成 30%，剩余 70%；从 30 改成 50 只新增 20%。同一比例允许再记用时，不重复增加内容量。

学习累计量仍从未删除学习记录推导。服务端以当日总计划量 × 新百分比减去已完成量，新增差量记录；不另存独立学习进度。学习记录修改、删除后，今日与原有进度同步重算。降低已保存的比例需要修改/删除原学习记录。

复习部分记录保存本次比例差量，掌握反馈为空；不改变下次复习日期，不新增首次学习记录。累计到 100% 才调用原有反馈用例。旧复习记录视为完整复习，其用时与历史依然展示。

## 一致性与失败处理

- 学习提交携带包含每日安排和当日学习记录版本的 SHA256 快照修订号。学习创建、编辑、删除及安排调整共用任务行锁；并发提交时只有一份有效快照可保存。
- 复习提交携带复习项版本，并锁定复习项；每次部分提交也递增版本。
- 重试使用同一 `clientToken`。成功后才关闭输入窗口、刷新清单；网络失败保留输入和令牌。409 要求关闭窗口、刷新核对后重新操作。
- 第一版离线只读。新今日快照含分区和后端合计，旧版快照提示联网更新，不推造新合计。不增加离线写入队列。

## API 与迁移

- `GET /api/today` 保留旧字段，新增 `sections`、`actualMinutes`、`remainingMinutes`、`missingEstimates`、`missingDurations`。
- `POST /api/learning/records/day-progress`：`date/taskId/completionPercent/durationMinutes/revision/clientToken`。
- `POST /api/review/records/day-progress`：`date/reviewItemId/completionPercent/durationMinutes/version/result/clientToken`。只有 100% 需要 result。
- 每日安排创建/调整请求与响应新增 `estimatedMinutes`。
- V13 从现有线上应用恢复；文件 SHA256 与线上字节一致：`8a5e5560c0d49047265b60ac1eb3554e6d10bb7969b82e1debab63ae5421a37b`。
- V14 增加每日预计用时、复习差量与估算快照；学习数量扩展为六位小数，避免小计划量的百分比差量被两位小数截断。V1–V12 未改写。

生产升级需先备份数据库与现有前后端产物，在隔离的 MySQL 8.4 验证从 V13 到 V14，再按现有 bundle 部署流程手动发布。已经产生部分复习记录后，旧版后端不兼容其空反馈，不能只替换旧 jar 回退；应使用兼容代码修复，或在明确可接受的数据恢复点恢复整套数据库备份。
