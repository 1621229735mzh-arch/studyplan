# 有序练习与每日名额

接续任务是显式选择的计划类型，不改变普通任务“未完成不自动顺延”的规则。

## 导入

使用 `schemaVersion: 2`，在任务上增加：

```json
"sequence": {
  "mode": "COMPLETE_THEN_ADVANCE",
  "items": [
    { "key": "31", "title": "LeetCode 31 · Next Permutation", "url": "https://leetcode.cn/problems/next-permutation/" }
  ]
}
```

数组顺序就是练习顺序，key 在任务内唯一。题目数等于任务计划总量，每条日安排为 1；本期最多每日完成一题。链接必须为 HTTPS。起止日期、日覆盖、月份与周说明、科目单位、事务追加和防重沿用原合同。v1 仍可导入普通任务，不能用描述文字开启接续。

预览显示有序清单与规则。未完成题不增加安排数量，漏做名额不累计，不自动延长结束日期。预计用时可以为 null。

## 执行及记录

- 今日显示具体题目及链接。完成整题使用“完成”，产生数量为 1 的记录；“记尝试”无需用时，不增加完成量或推进题目。
- 同一天已有完成记录时，今日保留当天实际题目，不切换成下一题；下一日期才使用下一个名额。
- 补记表单读取当前题目，提交携带 `sequenceItemId`。记录保存具体题目身份，修改学习内容不会改变题号；更正任务或题目归属需删除原记录后重新补记。
- 当前题为清单中第一道没有有效完成记录的题。修改数量为未完成或删除记录会恢复缺口，后续记录保留实际题目身份。只在连续无缺口时等价于“起始题号 + 完成题数”。
- 记录日期须在本期范围内。每天最多一个完成量，每题最多一个有效完成记录；不接受部分题量。取消日安排可移除或设为 0，原学习记录保留。
- 任务行锁串行化新建、修改、删除；记录版本防止覆盖，clientToken 防重复。今日 revision 包含本任务所有有效记录，跨日期的修改也使旧操作过期。

## 实现落点

V17 保存 `task_sequence`、`task_sequence_item` 和 `study_record.sequence_item_id`，不保存第二份完成游标。计划模块维护序列定义，学习模块派生完成情况和校验记录。`GET /api/learning/sequences/{taskId}?date=YYYY-MM-DD` 返回清单、第一道未完成题及日期展示题；普通任务返回空响应。所有接口沿用身份验证与 CSRF。

扩展目录及编辑题目顺序暂不开放；新一期使用独立计划导入。个人题目计划仍保存在忽略目录，不写入数据库迁移。

## 自行输入题号（2026-10-17）

SELECT_BY_NUMBER 是显式选择的新模式。今日完成或尝试均填写正整数 problemNumber，当前题为空且不自动推进；dayItem只显示当天真实记录。v7导入时items必须为空，运行时题目身份按输入建立，旧目录条目可保留用于历史追溯，但不作为待做清单。2026-10-19起每天可完成多题，今日页只填写本次新完成的题号，可批量或分次追加；原计划量仅作参考，不限制实际完成量。同题不重复增加首次完成量，历史尝试不计量且不计时。编辑原记录可更正题号，版本检查与事务保留。

GET /api/plan/tasks/{id}/problem-number-mode 返回任务、工作区、记录版本和按日期、ID排列的历史记录；POST携带全部历史记录的id、version、problemNumber与预览版本，原地转换并通过学习服务更正变化的题号。日期、原记录及数量保持；失败整体回滚。旧固定顺序模式不自动转换。

### 自填模式批量记录接口（2026-10-19）

`POST /api/learning/records/problem-numbers` 接收 `date`、`taskId`、`problemNumbers`（1至200个不重复正整数）、`revision` 与 `clientToken`。任务行锁串行化记录、修改和删除；整批在同一事务保存，重复已完成题号、日期超范围或修订过期时不保存任何新记录。相同令牌和列表重试返回原记录；增减、调序、更换题号或原记录已更正／删除均拒绝令牌重放。每题保留原学习记录身份和每题amount=1，课程题号列表及实际完成量按有效记录重算。兼容原单题day-progress及记录页接口；固定清单模式上限不变。
