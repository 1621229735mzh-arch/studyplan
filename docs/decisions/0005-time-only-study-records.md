# 0005 允许“只记时长”的学习记录

日期：2026-09-22
状态：已采纳

## 背景

最初实现把 `study_record.amount` 与 `unit_id`、`subject_id` 都设为必填：没有完成量就无法确定单位，
记录也就无法计入进度。

但 PLAN 二.2 有两处要求与“必须填完成量”冲突：

1. “允许计划外学习记录，**关联目标后再计入对应进度**”——这句话本身就意味着一条记录可以存在、
   却暂时不计入任何进度；
2. “学习时长、内容完成量和知识掌握情况**分别展示**”——时长与完成量是两个独立维度。

实际使用中也确实有这种情形：今天听了 35 分钟网课，只想记下用时，不想为它编造一个“单位”。

前端（`LearningRecordFormModel`）按 PLAN 的理解实现了“只记时长”的合法表单，
与后端校验不一致：提交会被 400 拒绝，界面只能把字段错误回显出来。

## 决定

以 PLAN 为准，放宽后端：

- 迁移 `V11` 把 `study_record.amount`、`unit_id`、`subject_id` 改为可空。
- 记录有三种合法形态：
  1. **关联任务**：科目与单位取自任务，可省略；
  2. **计划外且有完成量**：必须同时给出科目与单位（否则无法归入任何单位）；
  3. **只记时长**：不填完成量，也不要求科目与单位。
- 只记时长的记录：计入学习时长（`/api/today` 的 `studyMinutes`、`/api/progress/trend` 的时长趋势），
  不计入任何单位的完成量。
- 按单位的进度聚合显式过滤 `unit_id IS NOT NULL AND subject_id IS NOT NULL`，
  并在 XML 中注明这些记录的时长只出现在趋势里。
- 学习记录列表改为 `LEFT JOIN`，保证只记时长的记录不会从列表里消失。

## 影响

- 前端表单规则的“只记时长可以通过”成为正确行为，无需再改成强制填完成量。
- 单条记录的用时仍要求大于 0：一条既没有完成量、也没有用时的记录没有任何信息量。
- 相关验证：`PlanLearningFlowIntegrationTest.timeOnlyRecordCountsDurationOnly`、
  `adHocRecordWithAmountRequiresSubjectAndUnit`（有完成量时仍需科目与单位）。
- 前端按单位的图表不会把没有单位的时长算进某个单位，避免“凭空多出一个单位的数据”。
